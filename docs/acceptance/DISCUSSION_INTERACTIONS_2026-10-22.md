# Discussions 详情交互验证

本轮补齐详情页账号、草稿、网络调用和确认流程。以下是源码及主机测试范围，真实 GitHub 授权、完整应用导航、操作系统进程死亡和真机体验仍待验收。部分生产 NavHost 路径的后续主机验证见 [会话导航验证](CONVERSATION_NAVIGATION_2026-10-22.md)。

## 修复与行为

| 入口 | 状态与提交约束 |
| --- | --- |
| 详情、评论及楼中楼读取 | 绑定数值账号 ID；实际 IO 前核对当前账号及对应令牌；切号取消、隐藏旧内容，拒绝迟到结果；取消首屏后返回可重试读取 |
| 讨论编辑 | 整页表单支持 IME、窄屏和大字；当前不可编辑时不调用 API、不产生不确定写入提示；成功只清除当前编辑草稿，失败保留 |
| 顶层及楼中楼回复 | 各目标独立单飞；失败保留稿件，成功只清除对应稿件；结果未确认时再次发送需明确确认 |
| 评论编辑、删除 | 评论编辑使用现有整页编辑器，编辑稿按账号和目标保存；未输入就返回不会缓存旧正文，输入稿保留。删除确认不随页面保存状态恢复；页面作用域持有请求和结果，LazyColumn 回收不取消；成功清除对应编辑稿 |
| 标记/取消答案 | 展示讨论和评论预览；确认绑定数值账号和评论；账号、目标或权限变化使确认失效 |
| 返回与恢复 | 写入期间阻止页面返回；账号切换或离开页面取消请求，但保留可能已提交的标记；恢复草稿不恢复确认、也不自动重发 |
| 结果未确认 | 调用修改前持久化操作键，只有当前有效成功响应自动清除；读取刷新不清除标记、不写入。显式检查确认只清除本地提示并保留稿件 |
| 连接异常 | GraphQL 禁止连接重试及重定向；修改采用一次性正文，503 即时重试和断连不自动重放；取消实际 Call，包括正文读取 |

整页与展开的楼中楼随只读刷新重新加载；列表回收复用已读取连接。刷新失败给出提示。当前服务器返回的答案状态和评论数优先于旧保存统计。

## 回归证据

- `DiscussionDetailViewModelTest`：13 项，覆盖数字账号与目标隔离、SavedStateHandle 重建、排队切号、非合作迟到响应、单飞、失败保留、选择性清除、权限、取消与只读返回、未确认结果持久化及旧成功不能清除新标记。
- `GithubDiscussionsTransportTest`：7 项，覆盖实际 IO 账号/令牌绑定、无账号拒绝、503/断连不重放、302/307/308 不跨域提交，以及真实网络 Call 取消。
- `NativeDesignRenderingTest` 的 Discussions 方法：9 项，含已有长列表和目录测试，新增答案确认、删除确认不恢复、列表回收时删除继续完成、320dp/1.4 字体编辑失败保留、评论未改时使用最新正文及已输入稿保留，以及顶层/楼中楼不确定回复确认。
- 先前定向命令同时包含原 `GithubDiscussionsRepositoryImplTest` 和 `DiscussionsViewModelTest`，**58 项通过**；随后修改评论编辑入口并单独重跑 **9 项原生交互测试，全部通过**。两次存在重叠，不合计为独立场景；最终所有修改纳入完整套件，见 [统一验证记录](VERIFICATION_2026-10-22.md)。

开发过程中，快速 A→B→A 的 StateFlow 合并导致一次草稿恢复失败；补充下一协程轮次的会话核对后通过。之后新增界面测试有两项因标题、输入框及按钮共享“回复”文案而定位错误，改为定位可点击按钮后通过；未删除断言、关闭动画或增加超时。

评论编辑新增回归揭示未输入也缓存旧正文；修复时发现 AlertDialog 和尝试约束布局的 BasicAlertDialog 均无法在主机原生测试中空闲。最终复用已有整页评论编辑器，同样的最新正文与草稿断言通过。该现象不证明真机必现，真机布局、IME 和帧率仍需验收。

这些测试不构成写入幂等性证明。客户端无法判断响应丢失时服务端是否已提交，因此保留未确认提示并要求用户检查，不自动重发。真实远端写入须在明确指定的测试项目另行验收。
