# 设置排版与设备性能复查

## 修复及回归

设置、个人页等共用的 `GithubPreferenceRow` 原来每行使用 `BoxWithConstraints` 子组合，并按字符数判断摘要是否单行。新增原生回归先复现：16 个宽字符的摘要被单行省略，字符数无法可靠代表文案宽度。

现在使用单个 `Layout`，按两段文字的实际字形宽度、可用宽度和字体比例决定横排或上下排版；超长摘要完整换行。移除每行约束子组合，保留图标、箭头、56dp 最小行高、点击语义及 `placeRelative` 的 RTL 排列。没有缩短或禁用页面动画。

新增三项测试覆盖宽字形摘要完整显示及点击、320dp/1.5 字体换行与点击区域、RTL 文案顺序。最初三项中一项失败。实现过程中修正两处缺失导入；首次直接测量后文本段落宽度大于其 placeable，原溢出断言仍失败，改用有界 intrinsic 宽度作为精确测量约束后通过，没有删减断言。相关定向 3 类 / 34 项通过；随后 `scripts/verify-client.ps1` 全量验证通过：Debug / Release 各 130 类 / 1191 项测试，零失败、错误和跳过；Lint 129 / 131 警告、零错误。Rust 3 项、授权服务 5 项通过。覆盖率未测量。
