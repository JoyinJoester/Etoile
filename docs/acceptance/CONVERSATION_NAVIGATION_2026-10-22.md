# 会话页面生产导航图验证

本轮针对 CreatePR 与 Discussion 详情运行生产 `githubConversationsGraph`，使用真实 `NavHost`、`NavController`、`NavBackStackEntry` 生命周期及应用的四个导航过渡函数。主机环境为 Robolectric API 34、原生绘制、412×892dp，未禁用动画或调整空闲超时。

导航从完整应用容器收窄为七个现有 domain service 接口，生产应用继续传入相同实现。测试不创建凭据存储、网络客户端或安装产物；未覆盖的服务方法直接拒绝调用，所需详情读取由明确的本地替身实现。

## 七项主机回归

| 路径 | 断言 |
| --- | --- |
| Discussion 编辑→返回→覆盖页切号→返回 | B 不显示 A 的私有正文和草稿；返回 A 后手动重开恢复 A 标题、正文；仓库绑定数值账号，无写入 |
| 答案确认→覆盖页→返回，再切到同名不同 ID | 待确认状态不随导航或账号恢复；明确新确认只对 B 执行一次 |
| Discussion 编辑→返回→打开删除确认→保存并销毁宿主→新宿主恢复 | 讨论路由及草稿恢复；删除确认不恢复，不自动写入 |
| CreatePR 编辑→返回→覆盖页切 B→返回，再切 A | B 初始标题为空，不显示 A 草稿；返回 A 后恢复 A 标题、正文；无写入 |
| CreatePR 发送→宿主暂停→成功→恢复→返回列表 | 暂停期间不跳转；RESUMED 后仅进入创建的 PR 一次；返回不再次消费成功、不重发 |
| CreatePR 发送→覆盖页切 B→旧非合作成功→返回 A | 旧响应不导航、不清空原稿；B 不继承打开的编辑器，A 手动重开恢复原稿；仅一次模拟提交 |
| CreatePR 编辑→保存并销毁宿主→新宿主恢复 | 路由恢复，编辑器须手动打开；base、head、标题、正文保留；不提交、不消费虚构成功事件 |

保存恢复路径先调用 Activity 的保存状态回调，销毁原宿主，再将 Bundle 经过 Parcel 序列化/反序列化后交给全新 Activity。另断言 NavController 和当前条目的 ViewModelStore 与旧实例不同；这比只重建一个 SavedStateHandle 覆盖更多接线，但仍不是操作系统杀进程验收。

## 发现与修复

CreatePR 使用 `rememberSaveable(createAccountId)` 保存“正在编辑”。覆盖页切号、返回等保存恢复路径可能带回旧的打开状态；该标志并非草稿内容。现改为按账号的临时组合状态，文字仍保留在账号绑定的 SavedStateHandle 中。新宿主和重新进入页面后需手动打开编辑器；暂停/恢复同一页面不关闭正在编辑的内容。

测试搭建时修正了 Navigation 扩展函数导入；替身通过 Java Proxy 返回 Result 导致重复装箱，改为明确实现所需 PR 详情读取，未修改生产响应处理。列表本身有搜索输入框，因此编辑器关闭断言专门检查标题字段，避免误把搜索框认作编辑器。

## 范围边界

首页、账号选择和登录页在本测试中是占位目的地，会话流由测试驱动；没有证明真实账号选择 UI、完整应用导航外壳、真实授权、持久凭据、远端写操作或真机帧率。路由名称与页面操作来自生产实现，没有复制或简化被测会话导航逻辑。

7 项定向测试通过，随后纳入两个变体的完整验证。最终计数、源码及日志哈希见 [统一验证记录](VERIFICATION_2026-10-22.md) 与 [机器结果](verification-2026-10-22.json)。测试文件为 `GithubConversationNavigationTest.kt`，日志 `.codex-tmp/acceptance-conversation-navigation.log`。
