# GitHub 首页布局约定

## 目标

首页的三个一级目的地（收件箱、探索、个人资料）采用同一套 M3E 信息层级：

1. 顶部应用栏只负责显示当前页面标题和一个当前上下文相关的操作。
2. 页面内容从一个紧凑的说明行开始，说明行不重复页面标题。
3. 首屏只保留一个主任务：收件箱是登录/处理通知，探索是搜索，个人资料是账户入口。
4. 固定底部导航只承载一级目的地，二级设置和 GitHub 操作留在页面内容或详情页。

## 页面合同

| 页面 | 首屏顺序 | 交互原则 |
| --- | --- | --- |
| 收件箱 | 说明 → 登录提示或摘要 → 筛选 → 通知队列 | 未登录时提供唯一登录 CTA；已登录时摘要服务于分拣，不抢通知列表焦点 |
| 探索 | 说明 → 搜索框 → 搜索范围下拉 → 主题筛选 → 结果 | 五种搜索范围始终可见且不依赖横向滚动；主题可换行 |
| 个人资料 | 说明 → 登录提示或账户卡 → GitHub 快捷入口 → 应用偏好 | 登录提示是短卡片；账户入口按功能分组，所有行保持至少 48dp 触控高度 |

## 共享组件

- `GithubScreenIntro`：统一页面说明行，避免每个页面自行决定标题字号和间距。
- `GithubAuthPromptCard`：统一登录/未登录状态，保证 CTA、图标、辅助说明和触控区域一致。
- `GithubSearchScopePicker`：探索页搜索类型选择器，替代五项横向挤压的筛选条。
- `GithubWrappedFilterRow`：主题和少量筛选项采用换行布局，避免内容被屏幕边缘截断。
- `GithubPreferenceGroup` / `GithubPreferenceGroupDivider`：账户和偏好入口以分组表面呈现，便于后续增加入口而不破坏节奏。

## 性能与可访问性

- 每个一级页面只使用一个垂直滚动容器；列表使用稳定 key。
- 交互控件保留 Material 最小 48dp 触控尺寸，图标按钮提供内容描述。
- 动效仅用于页面切换和按压反馈，使用已有 160–240ms 动效 token，不做持续装饰动画。
- 文案全部来自资源，主题、语言和动态字体缩放不依赖页面硬编码颜色或尺寸。
