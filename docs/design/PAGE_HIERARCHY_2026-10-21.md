## 入口与状态检查

- 仓库主页 → 更多：typed route 只传 `fullName`，更多页面从对应仓库父导航项取得同一个 ViewModel。返回仅弹出当前项，不重建主页或丢失 Star / Fork 结果；从更多进入其他仓库功能时仍使用当前默认分支。
- 父路由身份保留原始大小写，不用 API 返回的规范仓库名替换：例如深链 `openai/Codex` 与 API 的 `openai/codex` 不会造成父导航项查找失败。讨论入口使用显式导航回调，不再通过 URL 字符串相等判断决定是否在应用内打开。
- 更多 → 主题编辑 / 管理：只向原 ViewModel 发送已有 action；权限使用当前状态计算。切换账号会取消旧请求并重建权限；管理确认和主题草稿以仓库和账号为 key。
- Fork：先显示确认，再发送原 `Fork` action；请求期间禁止重复点击，成功后入口改为打开已创建的复刻。
- 协作者移除 / 改权限：菜单先记录候选项，确认后清除候选并发原 action。候选以仓库、账号、权限为 key；确认时再次确认目标可管理，请求中禁用确认。
- PR 更多 → 合并：关闭管理菜单后打开合并表单，不清空 ViewModel。确认实时检查权限、忙状态、PR 开启状态和可合并状态；head SHA 改变会清除旧确认草稿。
- GitLab 修订：取消只恢复输入，不发加载请求；应用沿用原 `ApplyRef`，由 ViewModel 重置 revision / path / file 并重新加载。切换账号关闭对话框。
- GitLab 登录方式切换只改变表单展示；授权、取消、账号删除确认均沿用原处理路径。
- APK 下载前移只改变展示顺序，仍使用相同资源参数、下载去重和安装回调。
