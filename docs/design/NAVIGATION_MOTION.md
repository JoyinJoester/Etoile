# 页面过渡与返回开销

设置页及其子页面使用公共 NavHost 转场。原转场为 450ms，包含位移、缩放和不同曲线/时长的透明度动画；退出侧在位移完成前已完全透明，产生空档感，整页缩放与透明混合也增加绘制成本。

公共转场改为同一条 300ms FastOutSlowIn 曲线：新页面从容器边缘进入，旧页面后移五分之一宽度；返回时对应位置复原。页面保持原尺寸和不透明度，NavHost 固定背景并禁用尺寸插值，横向方向跟随布局方向。底部标签在固定视口内使用同步 180ms 淡变，取消额外位移和尺寸动画。

返回内容页时另有两项优化：贡献图按日索引在 `remember(calendar)` 内建立，每个日期只解析一次；Markdown 的 HTML/GFM 预处理与图片/引用索引移至后台，输入变化时取消旧任务。

`GithubNavigationTransitionsTest` 按 8ms 间隔采样不同视口宽度和 LTR/RTL 的前进/返回轨迹，检查页面覆盖、空隙及同步进度。Markdown、共享 UI 架构测试用于回归检查。

这些检查确认动画轨迹及编译正确，不提供设备帧率结论。真机仍需在首页、个人页、设置及外观子页之间往返，观察首进、返回和连续操作；本轮不生成 APK。
