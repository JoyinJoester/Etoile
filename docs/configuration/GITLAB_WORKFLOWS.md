# GitLab 协作流程

入口：GitLab 账号 → 选择并验证 → 我的 GitLab 项目 → 项目详情 → Issue / 合并请求 / 流水线。支持 GitLab.com 和使用 HTTPS 的自建实例及安装子路径。

## 已实现

| 模块 | 功能 |
| --- | --- |
| Issue | 状态筛选、服务端搜索、分页；创建、编辑标题/正文、评论、关闭和重开 |
| 合并请求 | 状态筛选、服务端搜索、分页；同项目源/目标分支创建、编辑标题/正文、评论、差异分页、关闭/重开、合并 |
| 流水线 | 按 ref 筛选、分页、详情；按 ref 创建、重试、取消 |
| 作业 | 分页列表、原始日志预览、重试、取消、手动执行 |

详情请求使用数字项目 ID 和项目内 `iid`；不把 Issue / MR 的全局 ID 当作编号。创建合并请求时源/目标分支必填且不同；编辑不会修改分支。搜索需点击应用筛选。返回列表或页面恢复前台时重新读取状态。

## 权限与确认

读取需要 `read_api`；协作写入需要 `api` 以及对应项目角色，保护分支、审批、CI 和实例策略仍由 GitLab 服务端裁决。OAuth 默认只申请 `read_user read_api`，明确开启协作写入后才增加 `api`。已有只读账号必须重新授权，不能通过刷新扩大权限。配置见 [GITLAB_AUTH.md](GITLAB_AUTH.md)。

关闭/重开、合并、创建/重试/取消流水线，以及执行/重试/取消作业都需二次确认，显示账号、实例、项目和目标。MR 合并前重读开放/草稿/可合并状态、源/目标分支和 Head SHA，PUT 携带 `sha`，不自动删除源分支。差异读取前后也校验页面 SHA，变化时拒绝展示并要求刷新；差异为预览，不提供行级评审。

创建流水线使用 GitLab 的单数 `/projects/:id/pipeline` 端点。输入 ref 表示服务端执行时该 ref 指向的最新提交，确认界面会提示可能运行更新的提交，不承诺锁定页面 SHA。作业操作和日志先重读作业并核对所属流水线。

普通创建、编辑和评论使用明确提交按钮。描述或评论任意一行去除前导空白后以 `/` 开头时，需额外确认，防止 GitLab 快捷命令隐藏执行状态变更或自动化；此路径遵循 GitLab 当时的状态，不具备专用合并按钮的 SHA 绑定保证。确认细节见 [DANGEROUS_ACTIONS.md](DANGEROUS_ACTIONS.md)。

## 状态、草稿与失败

创建/编辑/评论草稿以账号、项目、类型和目标隔离，导航 `SavedStateHandle` 支持进程重建后恢复；关闭编辑器保留草稿，成功提交才清除对应草稿。恢复不会自动提交，不恢复发送状态或快捷命令许可。合并成功退出编辑，尚未提交的编辑草稿保留。

账号切换或移除立即清空业务状态与日志，取消在途请求，并拒绝迟到结果。写入单飞，先取消旧读取防止覆盖成功状态；评论成功只追加服务端返回的评论。令牌仅在 data 层取得，必要时串行刷新，不进入页面、导航或草稿。

写请求和 OAuth 表单使用一次性请求体，关闭自动连接重试和重定向；断连、503 即时重试提示、错误响应和解析失败均不自动重发。结果不确定时保留草稿并提示先只读检查远端；刷新不会再次提交。401/403 提供账号页入口，详情读取无权限时清除旧详情。

## 预览限制

差异响应最多 2 MiB；单文件显示最多 32,000 字符和 300 行，过大、折叠或缺少 patch 时显示不可用。作业日志最多 1 MiB，超过限制明确提示；去除 ANSI/OSC 和终端控制字符，显示最多 5,000 行及每行 20,000 字符。不请求外链或远程 Markdown 图片，日志仅保存在当前页面内存。

## 验证与边界

MockWebServer 覆盖路径/JSON 编码、PAT/Bearer、分页、项目内编号、锁定检查、状态变更、SHA 绑定、审批/CI 阻挡、作业归属、日志限制、重定向及写入不重放。ViewModel 测试覆盖草稿恢复、账号隔离、单飞、失败保留、只读重试和迟到结果。全量测试与 Lint 结果记录在本文件的验收记录中。

本次范围是日常协作流程。尚未实现审批按钮、行级讨论线程、标签/指派人/里程碑编辑、跨项目 MR 创建、CI variables/artifacts、子流水线、GitLab 通知及高级项目管理。

自动化使用本机模拟服务，不使用真实令牌或写入远端；真实 GitLab.com / 自建实例 OAuth/PAT 权限及真机操作尚未联调。本轮未生成 APK。
