# Etoile 后续功能路线图

更新：2026-09-18。目标：可日常使用的第三方 GitHub Android 客户端。

本文是按交付顺序整理的功能规划，不是已交付清单。状态依据本地代码与实施记录；尚未核对 GitHub App 后台实际勾选的全部权限。已有接口或页面不等于通过真实账号验收。

## 第一期：日常客户端体验

| 模块 | 已有基础 | 后续交付内容 | 相关权限或依赖 |
| --- | --- | --- | --- |
| 登录与账号 | 浏览器/内置网页登录、设备代码、多账号、加密保存、刷新协调及授权服务代码 | 部署 GitHub App 授权服务；验证自动回调、过期刷新、退出与切号隔离；明确授权来源和重新授权入口 | 用户授权；服务端交换令牌，不在 APK 内嵌 GitHub App Secret |
| 界面与导航 | M3E 页面、紧凑布局调整、退出确认 | 继续缩小首页卡片；统一文字/图标基线、边距、列表密度；消除重复顶栏；完善返回、键盘、横屏及大字体适配 | 无新增 API 权限 |
| Issue | 列表、详情、创建、状态、标签、负责人、里程碑及评论管理代码 | 打通编辑/删除评论、模板、草稿恢复、筛选与错误重试；核验真实账号权限 | Issues 读写 |
| Pull Request | 列表、详情、差异、评审、合并及评审人相关代码 | 完整创建 PR、行内评论与回复、评审草稿、冲突/检查状态、合并方式选择；逐条验证现有操作 | Pull requests 读写；Contents、Checks、Commit statuses 按操作读取或写入 |
| Discussions | 列表、分类发帖、详情、回复、编辑、采纳回答代码 | 紧凑纯文本摘要；草稿恢复；分页/嵌套回复体验；补齐评论管理与真实 GraphQL 验证 | Discussions 读写 |
| 通知 | 收件箱、已读、完成、退订相关接口 | 筛选、准确跳转、批量操作、刷新与可配置提醒；验证不同令牌类型支持情况 | Notifications；逐端点核对 GitHub App 用户令牌支持，必要时保留 OAuth 兼容 |
| 社交与发现 | 搜索、Star、Watch、Fork、关注及用户列表基础 | 修复关注状态同步；完善 Star 分类、本地收藏、屏蔽用户和跨页一致性 | Starring、Watching、Followers、Blocking users；Fork 另核对仓库权限 |

本期验收：使用真实账号完成登录、浏览、创建、回复、评审及通知跳转；切换账号无旧数据或草稿串号；取消与失败不会丢失输入或误报成功。

## 第二期：代码、发布与自动化

| 模块 | 后续交付内容 | 相关权限或依赖 |
| --- | --- | --- |
| 文件与提交 | 在现有文件浏览基础上增加新建、编辑、删除、提交预览；处理文件已被他人更新的冲突；完善提交历史和比较 | Contents 读写；修改工作流文件另需 Workflows 写入 |
| 分支与标签 | 创建/删除分支和标签、选择提交基点、比较分支、显示保护规则 | Contents；修改保护规则另需 Administration |
| Release | 在现有浏览和下载基础上增加草稿、发布、编辑、删除、预发布标记、附件上传与删除 | Contents 读写 |
| Actions | 完善现有运行列表、日志、触发、取消、重跑、启停流程；增加产物下载、失败定位、工作流编辑与输入校验 | Actions 读写；Contents 与 Workflows 用于工作流文件编辑 |
| Projects | 调研新版 Projects API 后实现项目列表、条目、字段及状态管理，与 Issue/PR 关联 | 用户或组织 Projects 权限；按资源归属核对 GraphQL 支持 |

本期验收：每个写操作有结果回读；明确分支与提交目标；保护分支、冲突、上传中断、限流均有可恢复提示。

## 第三期：仓库管理

| 模块 | 后续交付内容 | 相关权限或依赖 |
| --- | --- | --- |
| 仓库设置 | 创建仓库、名称/描述/主题、默认分支、功能开关、可见性、归档/取消归档、删除 | Administration；删除必须核对具体端点及令牌类型，不沿用 OAuth scope 名称推断 GitHub App 权限 |
| 协作者与规则 | 在现有查看页面上补齐邀请、移除、角色调整；分支保护与规则集管理 | Administration；涉及组织团队时另需 Members |
| Secrets 与 Variables | 仓库/环境变量列表、新建、替换、删除；Secrets 通过公钥加密提交，只展示名称和元数据 | Secrets、Variables、Environments；无法读回已有 Secret 明文 |
| 环境与部署 | 环境配置、审批信息、部署历史、状态；按 API 支持提供管理操作 | Environments、Deployments；部分能力受仓库套餐限制 |
| Webhook | 在现有列表基础上增加创建、编辑、启停、删除、投递记录和重投 | Webhooks 读写 |
| Pages | 状态、构建记录、来源、域名与支持的配置项 | Pages；相关仓库设置按端点额外核对 |

本期验收：同时检查应用权限、用户角色及仓库授权范围；删除、移除成员、改变可见性等操作明确显示目标并确认；无权限时解释原因，不出现可点击但无反馈的按钮。

## 第四期：个人账号与组织管理

- 个人资料编辑、邮箱管理、Gist 创建/编辑/删除、SSH 公钥、SSH 签名公钥与 GPG 公钥管理。分别核对 Profile、Email addresses、Gists、Git SSH keys、Git signing SSH keys、GPG keys 等用户权限。
- 组织成员与邀请、团队与团队成员、团队仓库权限；组织变量、Secrets、Webhook 和可用设置。分别核对 Members、Administration 及对应组织权限。
- 对组织审批、SSO、用户角色、套餐限制提供明确说明；不承诺第三方 API 未开放的网页功能。

本期验收：个人与组织资源边界清晰；支持撤销授权后的恢复；不能通过增加 App 权限越过用户自身权限。

## 商店与体验贯穿各期

- 在已有 F-Droid 多源和 GitHub Release 解析基础上完善分类、搜索、来源管理及去重。
- Android 只提供可安装 APK，兼顾系统版本和 ABI；最新发布无 APK 时回溯最近兼容版本，并注明实际版本。
- 完善下载队列、取消/失败重试、更新检查、下载校验、签名和版本信息展示。
- 商店使用独立页面和单一顶栏；继续打磨参考 Droidify 的紧凑布局，以及参考 Capyreader 的阅读动效、底部继续滑动切换和右滑项目详情。
- 跨模块完善缓存、分页、加载/空态/错误态、限流提示、无障碍与深色模式。

## 授权和发布规则

1. App 后台新增权限不等于所有已有安装立即获得权限；按 GitHub 的安装批准及用户重新授权流程处理。
2. 用户令牌与安装令牌能力不同，个人账号操作不能一律改用安装令牌。逐端点验证权限，不承诺单一令牌覆盖全部 GitHub 功能。
3. 权限申请以已实现功能为依据；界面按实际能力显示操作与补充授权入口。
4. 每个功能需要接口验证、页面状态验证和必要的设备交互验证；发布前再做真实 GitHub 账号验证。使用模拟数据通过不标为真实端到端通过。
5. 当前 GitHub App 授权服务尚未完成公网部署和真实回调验收；这不阻止其他模块继续开发，但属于正式登录上线前置条件。

实施历史见 [CLIENT_ROADMAP.md](CLIENT_ROADMAP.md)，其中按时间追加的旧状态以较新记录及当前代码为准。本规划不设置未经估算的发布日期。
