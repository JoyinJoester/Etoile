# 危险操作确认检查

本轮检查范围为会删除远端内容、改变协作状态、执行自动化或修改仓库权限的现有入口。

| 操作 | 确认流程 |
| --- | --- |
| Actions 取消、重跑 | 本轮补齐，说明任务中断、重复部署和运行额度影响 |
| Workflow 启用、停用 | 本轮补齐，开关点击先确认，显示工作流名称与路径 |
| Issue / PR 关闭、重开、锁定、解锁 | 本轮补齐，显示会话编号、标题和影响 |
| 协作者权限变更 | 本轮补齐，显示仓库、账号与目标权限 |
| Webhook 启用、停用 | 本轮补齐，说明事件投递影响 |
| PR 合并 | 已有确认弹窗、合并方式及 Head SHA 校验 |
| 分支、标签删除 | 已有确认弹窗 |
| 文件删除 | 已有包含路径和提交说明的确认表单 |
| Release、发布附件删除 | 已有确认弹窗 |
| Release 发布、转回草稿 | 菜单先打开编辑器核对 tag、目标分支、说明及草稿开关；点击保存才提交，绑定确认时的数值账号 ID |
| Issue / PR 评论及 Discussion 回复删除 | 已有确认弹窗 |
| Discussion 标记/取消答案 | 显示讨论链接及评论预览，明确确认后单次提交；按数值账号 ID 和评论目标隔离，不恢复待确认状态 |
| Discussion 结果未确认后的重复回复 | 保留顶层和楼中楼草稿，先提示检查最新内容；再次发送需确认正文，取消不写入；刷新只读取数据 |
| 协作者移除、Webhook 删除、账号移除 | 已有确认弹窗；新增 GitLab 本机账号移除也使用确认 |
| Webhook 重新投递 | 确认仓库、Hook、投递 ID，并提示可能重复触发接收端构建/部署；提交期间禁止重复请求 |
| PR 评审回复切换讨论 | 已有非空草稿时，先确认丢弃旧草稿再打开另一讨论；取消保留正文和原目标，确认不跨任务恢复 |
| PR 解决/重新打开评审讨论 | 显示仓库、PR 和原评论预览；使用 GitHub 返回的当前账号权限，确认后单次调用 GraphQL，失败保留旧状态 |
| PR 批量提交评审 | 确认提交 SHA、评论数量、评审结论与总结；复核当前 Head 和开放/锁定状态，评论和结论一次发布 |
| PR 清空评审草稿、移除草稿评论、替换行编辑目标 | 均需确认；取消保留内容，确认不跨任务恢复；清理仅影响本地草稿 |
| 仓库可见性、归档、默认分支变更 | 已有确认，敏感变更要求输入仓库全名 |

新增共享确认组件只有在明确确认后才调用业务回调；取消、返回和点击弹窗外部不会调用。更改目标、操作或权限会使待确认状态失效，不跨进程恢复待确认操作。确认状态在调用业务前消费，避免同一次确认重复发送。

Actions 确认组件还绑定数值账号 ID 与 Run ID，同名且拥有相同权限的另一账号不能继承确认。Release 编辑草稿按账号、仓库和 Release 目标保存；切号关闭编辑器，手动重开可恢复文字，删除确认与附件选择不随草稿恢复。失败保留草稿，成功只清除当前目标的稿件，旧账号迟到响应不触发清除。

Workflow Dispatch 已有独立表单和明确提交按钮；普通评论、编辑表单及可恢复的 Star/关注操作沿用原流程。

Actions 的重跑/取消、Workflow 启停/Dispatch 和 Release 的创建/编辑/删除/上传/附件删除现携带界面确认账号。ViewModel 在入口、排队请求开始和结果回写前核对实时会话，仓库在后台实际取令牌时核对绑定数值账号及对应凭据，禁止使用切号后的替代账号。Workflow 启停确认由行组件自身绑定账号；Dispatch 为整页核对表单，打开标志不保存，按账号/仓库/工作流保存字段，切号关闭且不会自动提交。主机字段恢复、窄屏大字和网络账号证据见 [Actions / Release 账号验证](../acceptance/ACTIONS_RELEASE_ACCOUNT_BINDING_2026-10-22.md)。这不代替其他写入口的账号审查，也不保证已发送操作可以撤销。

CreatePR 文字草稿保留在账号绑定的 SavedStateHandle 中，编辑器是否打开只使用临时状态。覆盖页切号、重新进入或新宿主恢复后需手动打开；不会从导航保存状态继承旧编辑器。生产 NavHost 的主机回归验证暂停时不消费成功跳转、恢复后仅消费一次，切号后的旧成功不导航也不清空原稿；保存 Bundle 的新宿主恢复不自动提交。该证据不代替真实授权和操作系统杀进程验收。

Discussion 详情持续观察真实会话，草稿及结果未确认标记按数值账号、仓库和讨论编号隔离。提交前保存标记，仅收到当前会话接受的成功结果时自动清除；失败或取消保留，重建不自动提交。用户检查服务端后可明确清除本地提示，不触发远端写入。读取与修改在实际发送前复核绑定账号和对应令牌；GraphQL 请求不跟随重定向、不自动重试，修改使用一次性请求体，取消贯穿响应正文读取。评论编辑/删除及楼中楼发送由页面作用域持有，列表回收不取消请求；提交期间阻止返回。具体测试范围见 [Discussions 验证记录](../acceptance/DISCUSSION_INTERACTIONS_2026-10-22.md)。

Actions Run / Toggle / Dispatch 调用网络前同步保存持久未确认标记，仅当前会话接受的成功可自动清除。失败、取消或页面重建后保留提示；只读检查和本地“已检查”不重发。重复执行须新的明确确认，字段或数值账号变化使旧确认失效；存储不可读或不能提交标记时禁止发送。生产注入同一个应用级 journal，键值不保存令牌、ref、inputs 或正文。具体证据和边界见 [Actions 未确认结果](../acceptance/ACTIONS_UNCERTAIN_OUTCOMES_2026-10-22.md)。

## GitHub 公共请求保护

资源 API 的公共传输层对非 GET/HEAD/OPTIONS 请求使用一次性请求体，并关闭自动连接重试和重定向；无请求体的 DELETE 也使用一次性空请求体。这样服务端已接收后断连或返回 `503 + Retry-After: 0` 时不会自动重新发送。派生客户端保留认证、拦截器及上传超时，协程取消会关闭实际 Call，覆盖响应正文读取。

11 个请求文件的 56 个调用已接入，13 类代表操作的传输矩阵及辅助测试通过；GraphQL POST 查询保守采用同样策略，GET 仍沿用读取策略。OAuth 令牌端点、部分直接执行的只读请求不在此次范围内。拒绝重定向后，仓库移动等场景可能要求用户核对新的目标地址。

网络失败与取消不能证明远端未执行；相关失败提示要求先检查最新状态。除已有专门保护的入口外，不能把提示文案视为持久未确认状态或再次发送确认，也不能据此推断所有写操作均已绑定确认账号。多请求批量操作也不具备原子性。详细证据见 [GitHub 写入传输验证](../acceptance/GITHUB_MUTATION_TRANSPORT_2026-10-22.md)。

## GitLab 协作

GitLab 复用上述确认组件。确认目标显示账号、实例、项目 ID 和具体资源，切换账号或目标后原确认失效；不保存待确认状态。

| 操作 | 确认与发送约束 |
| --- | --- |
| Issue / 合并请求关闭、重开 | 展示编号、标题、当前状态；发送前重新读取状态，拒绝已合并目标 |
| 合并请求合并 | 展示源/目标分支与完整 Head SHA；重读可合并状态、分支及 SHA，PUT 携带 `sha`，保留源分支 |
| 创建流水线 | 展示 ref，并说明针对服务端执行时的最新提交运行，可能触发部署或费用 |
| 流水线重试、取消 | 展示流水线 ID 和 ref；重读当前状态后单次执行 |
| 作业手动执行、重试、取消 | 展示流水线、作业名称与 ID；重读作业并核对所属流水线 |
| 描述或评论中的 `/` 快捷命令 | 单独确认完整正文；说明命令可能改变状态或执行自动化，按服务端当前状态处理，不绑定本页 SHA |

普通创建、编辑和评论仍直接提交。只有包含快捷命令时增加确认；草稿恢复不恢复快捷命令许可。写入单飞，不跟随重定向，使用一次性请求体阻止连接重试及 503 即时重试造成重复执行。失败保留草稿并提供只读检查入口，刷新和重试读取不会重发写入。

MockWebServer 与 ViewModel 回归覆盖锁定/状态/权限、Head 变更、作业归属、取消与迟到结果，以及断连和 `Retry-After: 0` 不重复发送。真实实例权限与设备交互仍需联调，自动化未修改远端资源。
